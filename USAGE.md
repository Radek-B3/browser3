# Browser3 CLI & Automation Guide

This guide documents the controls present in Browser3. Profile launch, sticky proxy
management, opt-in CDP automation, and isolated desktop mode are part of the supported
workflow.

---

## 1. Profile Generation & Host Measurement

Browser3 uses measurements from the physical host as inputs to profile generation and coherence checks.

### Host Probe (`scripts/probe_host.py`)

Before profiles can be generated on a new machine, the host probe measures your system's actual hardware characteristics. This runs automatically on first launch, or you can run it manually:

```powershell
# Measure the host hardware and cache characteristics
python scripts/probe_host.py

# Force a re-measurement after a GPU, driver, monitor, or major font update
python scripts/probe_host.py --force
```

The probe records:
- Primary GPU vendor, device ID, subsystem ID, driver version, and DirectX capability
- Monitor resolution, work area, color depth, and display scaling level
- Installed system font inventory
- Operating system version, build number, and system locale

Probe results are stored locally in `%LOCALAPPDATA%\Browser3\cache\host_current.json`.

### Profile Generation (`generate_profiles.py`)

Profiles are generated by combining the host probe measurements with deterministic per-profile seeds. If profiles do not exist, the launcher generates default profiles 1..5 automatically on first run, or you can run the generator explicitly:

```powershell
python generate_profiles.py
```

- Generates five deterministic profile configurations in `%LOCALAPPDATA%\Browser3\profiles`.
- Each configuration has a 256-bit seed (`profile_id`) used for deterministic per-profile selections.
- **Portability note:** Copying a profile to another physical machine is unsupported because its hardware claims would no longer match the host.

## 2. Command-Line Interface (CLI)

The primary entry point is `.\browser3` (or `python launcher.py`). It manages profile locks, optional proxy tunnels, desktop environments, and Chrome process lifecycle.

### Quick Commands

```powershell
# Create and launch a fresh profile (auto-initializes on first run)
.\browser3

# Launch a specific profile
.\browser3 --profile 2

# Launch directly using host network (ignores proxy.txt)
python launcher.py --profile 1 --no-proxy

# Start with opt-in CDP automation for Playwright / Puppeteer
python launcher.py --profile 1 --control cdp

# Combine CDP automation with isolated Win32 background desktop
python launcher.py --profile 1 --control cdp --desktop isolated

# Print the full command line without starting Chrome
python launcher.py --profile 1 --dry-run
```

### Full CLI Options Reference

| Argument | Values / Type | Default | Description |
|---|---|---|---|
| `--profile` | `int` (1..N) | New profile | Select an existing profile index; without it, create and launch a fresh profile. |
| `--all` | Flag | `False` | Launch all generated profiles sequentially. |
| `--with-proxy` | Flag | Auto | Force sticky proxy assignment (default when `proxy.txt` contains entries). |
| `--no-proxy` | Flag | `False` | Bypass proxies and connect directly through the host network. |
| `--control` | `none`, `cdp` | `none` | Enable Chrome DevTools Protocol (CDP) for browser automation. |
| `--desktop` | `current`, `isolated` | `current` | Choose between the active desktop or an isolated Win32 background desktop. |
| `--control-output` | `file_path` | `None` | Optional path to write the JSON control hand-off metadata. |
| `--dry-run` | Flag | `False` | Output the complete Chromium command-line string without execution. |
| `--gpu` | `off`, `family`, `common`, `all` | Host-dependent for new profiles | GPU identity mode for profile generation / override; existing profiles are unchanged when omitted. |

## 3. AI Agent & Playwright Automation Controls

Browser3 includes opt-in CDP support for Playwright, Puppeteer, and custom automation
clients. Default launches keep CDP disabled (`--control none`) to ensure normal browsing
sessions remain completely CDP-free.

### Launching with CDP (`--control cdp`)

When started with `--control cdp`, the launcher assigns a loopback port and emits a JSON
control payload:

```powershell
python launcher.py --profile 1 --control cdp
```

**Payload shape:**
```text
BROWSER3_CONTROL {"profile": 1, "control": "cdp", "cdp_url": "ws://127.0.0.1:54321/devtools/browser/...", "pid": 12345, "desktop": "current", "desktop_name": null}
```

If `--control-output control.json` is passed, the same JSON metadata is written to the specified file.

### Local Session API

The release includes the optional loopback-only Session API:

```powershell
python browser3_agent.py --listen 127.0.0.1 --port 17890
```

It prints a ready JSON object and exposes `GET /v1/health`,
`POST /v1/sessions`, `GET /v1/sessions`, and
`DELETE /v1/sessions/{session_id}`. A minimal PowerShell start request is:

```powershell
$body = @{
  profile = 1
  proxy = $false
  build = "Release"
  control = "cdp"
  desktop = "current"
} | ConvertTo-Json

Invoke-RestMethod -Method Post `
  -Uri http://127.0.0.1:17890/v1/sessions `
  -ContentType application/json `
  -Body $body
```

The API manages Browser3 process lifecycle and profile locks. It does not perform page
automation; connect Playwright, Puppeteer, or another client to the returned loopback
`cdp_url`.

### Playwright Integration (Node.js)

Connect over CDP using `playwright-core`:

```javascript
import { chromium } from "playwright-core";

// Connect to the loopback CDP endpoint provided by launcher or Session API
const browser = await chromium.connectOverCDP(cdpUrl);
const context = browser.contexts()[0];
const page = context.pages()[0] || await context.newPage();

await page.goto("https://example.com");
console.log(await page.title());

// Disconnect Playwright (process lifecycle is managed by launcher or Session API)
await browser.close();
```

### Playwright Integration (Python)

Connect over CDP using `playwright`:

```python
from playwright.sync_api import sync_playwright

with sync_playwright() as playwright:
    browser = playwright.chromium.connect_over_cdp(cdp_url)
    context = browser.contexts[0]
    page = context.pages[0] if context.pages else context.new_page()
    page.goto("https://example.com")
    print(page.title())
```

### Automation Invariants & Guarantees:
- **Zero Injected JS Hooks:** No Proxy objects, runtime scripts, or `Page.addScriptToEvaluateOnNewDocument` hooks are used for fingerprinting. All masking is in native C++.
- **Loopback Only:** CDP endpoints bind exclusively to `127.0.0.1` on a dynamically assigned non-zero port.
- **Single-Instance Profile Lock:** OS-level locking prevents concurrent write collisions on the persistent profile directory.
- **Context Preservation:** Reopening a profile preserves cookies, storage, and identity determinism.

## 4. Experimental Isolated Desktop (`--desktop isolated`)

Browser3 includes an experimental **Isolated Win32 Desktop** launch path for running a
headful browser outside the user's active desktop:

```powershell
python launcher.py --profile 1 --control cdp --desktop isolated
```

### How it works:
- Browser3 creates an isolated desktop in the interactive window station (`WinSta0\Browser3_Desk_<token>`).
- The same configured Chromium runtime launches in headful mode; the normal hardware and host-coherence preflight still applies.
- The browser window stays outside the active desktop, which is intended to avoid taking focus from the user's visible session.

## 5. Proxy & Network Management

Browser3 implements persistent proxy routing and proxy-derived locale/time-zone alignment.
The current release gate was completed without a proxy, so proxy and multi-geo operation
are not part of that release's tested GO.

### `proxy.txt` Syntax

Place `proxy.txt` in the root directory next to `launcher.py`. Supported formats include:

```text
# HTTP proxy without authentication
192.0.2.10:8080

# HTTP proxy with username and password
192.0.2.11:8080:username:password

# HTTP URL format
http://username:password@192.0.2.12:8080

# SOCKS5 proxy (with or without authentication)
socks5://username:password@192.0.2.13:1080
```

### Key Networking Features:

1. **Sticky Mapping:**
   Profiles are paired with a proxy in `%LOCALAPPDATA%\Browser3\state\profile_proxy_map.json`. The mapping persists across launches while the proxy list remains compatible.
2. **GeoIP Auto-Alignment:**
   When a proxy is used, the launcher queries the proxy exit address via `ip-api.com` through the proxy tunnel. It aligns:
   - Browser-visible time zone (`Intl.DateTimeFormat`)
   - `navigator.languages` and `Accept-Language` headers
   - Regional font bundle visibility
3. **WebRTC Protection:**
   Browser3 sets `disable_non_proxied_udp` when a proxy is enabled to block non-proxied UDP paths.
4. **Credential Loopback Forwarder:**
   Chromium CLI does not support embedded credentials in `--proxy-server`. For authenticated proxies, Browser3 starts a local TCP tunnel (`127.0.0.1`) that injects `Proxy-Authorization` without terminating the browser's end-to-end TLS connection.

## 6. Storage Locations & System Troubleshooting

### Data Storage (`%LOCALAPPDATA%\Browser3`)

| Directory / File | Contents |
|---|---|
| `profiles/profile_NN.json` | Generated identity configuration |
| `profiles/_userdata/profile_NN` | Chromium user data directory (cookies, storage, history) |
| `cache/host_current.json` | Host probe measurements |
| `cache/proxy_geo_cache.json` | Cached proxy GeoIP responses |
| `state/profile_proxy_map.json` | Persistent profile-to-proxy mapping |
| `logs/` | Runtime diagnostic logs |

### Common Issues & Troubleshooting

- **Hardware Acceleration Required:**
  Browser3 requires a physical GPU with working DirectX 11 / D3D11 acceleration. Software fallback adapters such as SwiftShader are rejected by preflight.
- **Windows N/KN Media Feature Pack:**
  If video playback (H.264 / AAC) fails on Windows N or KN editions, install the official Microsoft Media Feature Pack.
- **Stale Profile Lock:**
  Each profile uses a single-instance lock (`.browser3-profile.lock`) in its user-data directory to prevent concurrent writes. If a previous run terminated abruptly, ensure the process has stopped before relaunching.
- **DRM Services:**
  Widevine DRM is not included, so services that require it are unsupported.
