# Browser3 CLI & Automation Guide

This guide provides a comprehensive reference for launching, configuring, and automating Browser3 profiles through the command-line interface (CLI) and AI agent workflows.

---

## 1. Profile Generation & Host Measurement

Browser3 profiles are built around the physical host to ensure that all hardware and platform signals remain coherent and realistic.

### Host Probe (`scripts/probe_host.py`)

Before profiles can be generated on a new machine, the host probe measures your system's actual hardware characteristics:

```powershell
# Measure the host hardware and cache characteristics
python scripts/probe_host.py

# Force a re-measurement after a GPU, driver, monitor, or major font update
python scripts/probe_host.py --force
```

The probe records:
- Primary GPU vendor, device ID, subsystem ID, driver version, and DirectX capability
- Monitor resolution, work area, color depth, and display scaling level
- Installed system font inventory
- Operating system version, build number, and system locale

Probe results are stored locally in `%LOCALAPPDATA%\Browser3\cache\host_current.json`.

### Profile Generation (`generate_profiles.py`)

Profiles are generated by combining the host probe measurements with deterministic per-profile seeds:

```powershell
python generate_profiles.py
```

- Generates 5 distinct profiles in `%LOCALAPPDATA%\Browser3\profiles`.
- Each profile receives a unique, deterministic 256-bit seed (`profile_id`) that governs per-profile text-rendering edging and regional font bundle selection.
- **Portability note:** Profiles cannot be copied to another physical machine because their hardware claims would no longer match the underlying host.

## 2. Command-Line Interface (CLI)

The primary entry point is `launcher.py`. It manages profile locks, optional proxy tunnels, desktop environments, and Chrome process lifecycle.

### Quick Commands

```powershell
# Launch default profile 1 (creates it automatically if not present)
python launcher.py

# Launch a specific profile
python launcher.py --profile 2

# Launch directly using host network (ignores proxy.txt)
python launcher.py --profile 1 --no-proxy

# Launch with CDP automation enabled for AI agents
python launcher.py --profile 1 --control cdp

# Launch headful in an isolated background desktop
python launcher.py --profile 1 --control cdp --desktop isolated

# Print the full command line without starting Chrome
python launcher.py --profile 1 --dry-run
```

### Full CLI Options Reference

| Argument | Values / Type | Default | Description |
|---|---|---|---|
| `--profile` | `int` (1..N) | `1` | Select the profile index to launch. |
| `--all` | Flag | `False` | Launch all generated profiles sequentially. |
| `--with-proxy` | Flag | Auto | Force sticky proxy assignment (default when `proxy.txt` contains entries). |
| `--no-proxy` | Flag | `False` | Bypass proxies and connect directly through the host network. |
| `--control` | `none`, `cdp` | `none` | Enable Chrome DevTools Protocol (CDP) for browser automation. |
| `--desktop` | `current`, `isolated` | `current` | Choose between the active desktop or an isolated Win32 background desktop. |
| `--control-output` | `file_path` | `None` | Optional path to write the JSON control hand-off metadata. |
| `--dry-run` | Flag | `False` | Output the complete Chromium command-line string without execution. |
| `--gpu` | `off`, `family`, `common`, `all` | `common` | GPU identity mode for profile generation / override. |

## 3. AI Agent & Automation Integration

Browser3 supports native integration with AI agents and automation frameworks (such as Playwright, Puppeteer, or custom CDP clients) while maintaining full fingerprint consistency.

### Starting with Automation (`--control cdp`)

When started with `--control cdp`, the launcher assigns a clean loopback port for DevTools and emits a standardized JSON control payload on standard output:

```powershell
python launcher.py --profile 1 --control cdp
```

**Stdout handshake line:**
```text
BROWSER3_CONTROL {"profile": 1, "control": "cdp", "cdp_url": "ws://127.0.0.1:54321/devtools/browser/...", "pid": 12345, "desktop": "current", "desktop_name": null}
```

If `--control-output control.json` is passed, the same JSON dictionary is written to the specified file for easy process hand-off.

### Playwright Integration Example (Python)

```python
import json
import subprocess
from playwright.sync_api import sync_playwright

# 1. Start Browser3 in CDP mode
cmd = ["python", "launcher.py", "--profile", "1", "--control", "cdp", "--control-output", "control.json"]
proc = subprocess.Popen(cmd)

try:
    # 2. Read the emitted control metadata
    with open("control.json", "r", encoding="utf-8") as f:
        control_info = json.load(f)
    cdp_url = control_info["cdp_url"]

    # 3. Connect Playwright over CDP
    with sync_playwright() as p:
        browser = p.chromium.connect_over_cdp(cdp_url)
        context = browser.contexts[0]
        page = context.pages[0] if context.pages else context.new_page()

        page.goto("https://example.com")
        print("Page title:", page.title())
finally:
    proc.terminate()
```

### Playwright Integration Example (Node.js)

```javascript
import { chromium } from 'playwright';
import { readFileSync } from 'fs';

// Read the endpoint from control-output JSON
const control = JSON.parse(readFileSync('control.json', 'utf8'));

const browser = await chromium.connectOverCDP(control.cdp_url);
const context = browser.contexts()[0];
const page = context.pages().length ? context.pages()[0] : await context.newPage();

await page.goto('https://example.com');
console.log('Title:', await page.title());
await browser.close();
```

## 4. Background Automation on Isolated Desktop (`--desktop isolated`)

Headless browser modes (`--headless`) are easily detected by modern anti-bot systems because they disable GPU compositing, alter font rendering, and modify internal timing loops.

Browser3 solves this on Windows using **Isolated Win32 Desktops**:

```powershell
python launcher.py --profile 1 --control cdp --desktop isolated
```

### How it works:
- Browser3 creates an isolated desktop in the interactive window station (`WinSta0\Browser3_Desk_<token>`).
- Chromium runs as a genuine **headful** process with full hardware GPU acceleration, DirectX D3D11 rendering, and standard screen metrics.
- The browser window is visually contained within the isolated desktop, preventing AI agents or scrapers from stealing mouse focus or interfering with the user's active desktop.

## 5. Proxy & Network Management

Browser3 provides automatic, persistent proxy routing with network-to-fingerprint coherence.

### `proxy.txt` Syntax

Place `proxy.txt` in the root directory next to `launcher.py`. Supported formats include:

```text
# HTTP proxy without authentication
192.0.2.10:8080

# HTTP proxy with username and password
192.0.2.11:8080:username:password

# URL format (HTTP / HTTPS)
http://username:password@192.0.2.12:8080

# SOCKS5 proxy (with or without authentication)
socks5://username:password@192.0.2.13:1080
```

### Key Networking Features:

1. **Sticky Mapping:**
   Profiles are persistently paired with their proxy in `%LOCALAPPDATA%\Browser3\state\profile_proxy_map.json`. Profile 1 consistently uses the same exit node across restarts to avoid suspicious location jumping.
2. **GeoIP Auto-Alignment:**
   When a proxy is used, the launcher queries the proxy exit address via `ip-api.com` (routed through the proxy tunnel). The browser automatically synchronizes:
   - System timezone (`Intl.DateTimeFormat`)
   - `navigator.languages` and `Accept-Language` headers
   - Regional font bundle visibility
3. **WebRTC Protection:**
   Browser3 enforces `disable_non_proxied_udp` when a proxy is enabled to ensure WebRTC traffic cannot bypass the proxy and expose your real public IP.
4. **Credential Loopback Forwarder:**
   Chromium CLI does not support embedded credentials in `--proxy-server`. For authenticated proxies, Browser3 starts a local TCP tunnel (`127.0.0.1`) that injects `Proxy-Authorization` without terminating TLS, preserving native JA3, JA4, and HTTP/2 TLS fingerprints.

## 6. Storage Locations & System Troubleshooting

### Data Storage (`%LOCALAPPDATA%\Browser3`)

| Directory / File | Contents |
|---|---|
| `profiles/profile_NN` | Chromium user data directory (cookies, storage, history) |
| `cache/host_current.json` | Host probe measurements |
| `cache/proxy_geo_cache.json` | Cached proxy GeoIP responses |
| `state/profile_proxy_map.json` | Persistent profile-to-proxy mapping |
| `logs/` | Runtime diagnostic logs |

### Common Issues & Troubleshooting

- **Hardware Acceleration Required:**
  Browser3 requires a physical GPU with working DirectX 11 / D3D11 acceleration. Virtual machines without GPU pass-through or software adapters (SwiftShader) are rejected during startup to prevent high tampering anomaly scores.
- **Windows N/KN Media Feature Pack:**
  If video playback (H.264 / AAC) fails on Windows N or KN editions, install the official Microsoft Media Feature Pack.
- **Stale Profile Lock:**
  Each profile uses a single-instance lock (`profile.lock`) in its `user-data-dir` to prevent concurrent writes. If a previous run terminated abruptly, ensure the process has stopped before relaunching.
- **DRM Services:**
  Widevine DRM is intentionally not included. Commercial DRM-protected streaming services (Netflix, Spotify, etc.) are unsupported.
